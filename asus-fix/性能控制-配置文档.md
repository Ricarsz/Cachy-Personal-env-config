## 1. 性能控制架构

性能控制分三层协作，**只有 asusctl 一个电源管理入口**（PPD 已弃用）：

```
┌─ 用户层 ─────────────┐
│  asusctl (CLI)       │
│  rog-control-center  │ ← 图形界面，控制档位/风扇/灯效/TDP
│  Fn+F5 (原生切档)    │
├─ 守护层 ─────────────┤
│  asusd               │ ← 华硕硬件守护，唯一电源档位管理者

│  asus-armoury        │ ← TDP/固件控制
│  asus-nb-wmi         │ ← 键盘/风扇/电池/热键
│  nvidia-powerd       │ ← NVIDIA GPU 动态功耗
│  k10temp             │ ← CPU 温度监控
└─────────────────────┘
```

## 4. amd_pstate 修复记录（关键）

### 4.1 背景

8845H 的 BIOS 清除了 `X86_FEATURE_CPPC`，且 `_CPC` 表中 **AUTO_SEL_ENABLE 写成整数占位值**（`0x00000001`）而非 GAS，导致 `amd_pstate` 初始化失败（`failed to set auto_sel, ret: -95` → EOPNOTSUPP），回退 `acpi-cpufreq`。

### 4.2 修复内容（⚠️ 2026-09-05 v2 架构，替换旧占位表方案）

通过 **ACPI 表覆盖** 修正固件表。⚠️ 覆盖匹配 = 签名+OEM ID+OEM Table ID 三重相同 + OEM Revision 更高
（内核 acpi_table_initrd_override 语义）。AMD AGESA 全部 SSDT 共用身份 `SSDT/AMD/AmdTable`，
本机共 2 张：#1=ALIB 表（33814B）、#2=_CPC 表（21630B，AUTO_SEL 占位整数损坏）。

| 文件 | 内容 | 版本 |
|---|---|---|
| `/etc/initcpio/acpi_override/01-amdalib.aml` | **ALIB 表原样复原**（33814B，零内容改动） | rev 2→3 |
| `/etc/initcpio/acpi_override/02-amdcpc.aml` | 16 个 CPU `_CPC` 的 AUTO_SEL_ENABLE 整数 → `Register(FFixedHW,1,1,0xC00102B1)`（177 对象零丢失，iasl 重编译） | rev 3→4 |

❌ 旧方案（SSDT1 占位表 + SSDT3.aml）已废弃：占位表按序顶掉了 ALIB 表，
导致 AC 适配器 _PSR/温控 _SCP/WWAN/VGA 电源/TDP 写入全部断裂（-EIO）。
原始 AML 备份与全过程分析: `~/acpi-fix-workdir/`。

配套修改：
- `/etc/mkinitcpio.conf`：HOOKS 含 `acpi_override`（备份: `~/acpi-fix-workdir/mkinitcpio.conf.bak`）
- `/etc/default/limine`：内核参数含 **`amd_pstate=passive`**
- initramfs 已重新生成

### 4.3 为什么是 passive 不是 active

- 内核默认模式 `CONFIG_X86_AMD_PSTATE_DEFAULT_MODE=3`（active）
- 但 BIOS 限制 CPPC（共享内存机制，无 `X86_FEATURE_CPPC`），active 实测报 `ENODEV`
- **EPP 属性（`energy_performance_preference`）只在 active 模式暴露**（内核 `epp_visibility()`），故 passive 模式下 EPP 不可用，asusd 的 `profile_*_epp` 设置无效果（无害）

### 4.4 验证结果

- `scaling_driver`：**amd-pstate**
- `amd_pstate/status`：**passive**
- 16 个逻辑核全部初始化成功
- 频率范围：1.1–5.14 GHz
- governor：`schedutil`
- **ACPI ALIB 表完整加载**（7 张 SSDT 含 ALIB），AC 适配器设备 ACAD 正常注册
- 日志仅剩华硕固件固有噪音（WWAN/RTL8 引用不存在，Windows 同样存在）

### 5.1 性能档位（asusd.ron 核心）

```

platform_profile_on_battery: Performance
change_platform_profile_on_ac:     false
change_platform_profile_on_battery: false
```

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志 `CPPC ... disabled by the BIOS` | BIOS 限制 CPPC | **正常**，passive 模式可用，无需处理 |
| 日志 `energy_performance_preference not found` | passive 模式无 EPP 属性 | **正常**，asusd 无害跳过 |
| `amd_pstate` 回退 `acpi-cpufreq` | ACPI 覆盖未生效 | 检查 `/etc/initcpio/acpi_override/` 两个 .aml 存在、`mkinitcpio.conf` 有 `acpi_override` hook、`amd_pstate=passive` 在内核参数 |
| 风扇曲线失效 | 档位切换后未应用 | `asusctl fan-curve --mod-profile <档位> --enable-fan-curves true` |
| 桌面电源菜单错乱 | 依赖 PPD | **预期**：已禁用 PPD，改用 asusctl/rog-control-center |
| 开机 ACPI 报 ALIB/ACAD/_PSR 错误 | 覆盖表缺失或被误顶 | 检查 `grep -l ALIB /sys/firmware/acpi/tables/SSDT*`（须有 7 张命中）；确认 HOOKS 含 acpi_override 且 initramfs 已重建 |
| TDP 写入 -EIO / RCC 显示驱动未加载 | ALIB 断裂（覆盖表问题） | 同上；恢复 01-amdalib 后写入立即恢复 |

## 9. 还原流程（如果换机/重装）

1. 恢复 `/etc/initcpio/acpi_override/` 的 01-amdalib.aml + 02-amdcpc.aml
2. `mkinitcpio.conf` 确保 HOOKS 含 `acpi_override`
3. 重新生成 initramfs：`sudo mkinitcpio -P`
4. `/etc/default/limine` 内核参数加 `amd_pstate=passive`，然后 `sudo limine-update`
   （⚠️ 2026-09-04 教训：直接改 `/boot/limine.conf` 会在下次 `limine-update` 时被
   `/etc/default/limine` 覆盖丢失，表现为 `scaling_driver` 回退 `acpi-cpufreq`、
   日志出现 `failed to set auto_sel, ret: -5`×16、频率范围缩水到 1.6–3.8GHz）
5. 安装 `asusctl rog-control-center`
6. 恢复 `/etc/asusd/asusd.ron` 和 `profile.conf`
7. 重启验证
